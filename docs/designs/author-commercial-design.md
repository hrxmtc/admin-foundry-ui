# 墨鱼作者端：上市功能与页面设计建议

> 版本：v0.2｜日期：2026-11-11｜状态：设计评审稿
>
> 墨鱼就是当前 c-foundry 作者端。本文规划现有产品的增量，与[上市 PRD](commercial-launch-prd.md)、[后台设计 Brief](admin-design-brief.md)、[后台页面地图](admin-page-map.md)及[跨端流程](commercial-cross-app-flows.md)共同评审。

功能与验收要求见[作者端上市 PRD](author-launch-prd.md)；本文负责页面组织和交互建议。共同商业规则与待决事项仍以[上市总 PRD](commercial-launch-prd.md)为准。

## 1. 作者端如何组织

建议围绕“创作空间、账户与服务、老墨”组织功能。登录后的稳定落点继续是我的作品；会员、购买与求助通过账户区域和具体任务进入，作者不需要先经过商业化首页才能写作。

| 区域       | 作者要完成的事                           | 设计位置                                     |
| ---------- | ---------------------------------------- | -------------------------------------------- |
| 创作空间   | 管作品、规划、写作、审阅与导出           | 复用现有作品、创意、剧本、工作台及其导航     |
| 账户与服务 | 管会员、额度、购买、费用、工单与账户设置 | 账户菜单进入作者中心，中心内有清楚的二级导航 |
| 老墨       | 查技巧、交流、发帖、看审核和回复         | 非专注创作页面有稳定入口；社区有自己的导航   |
| 公开说明   | 了解产品、价格、帮助及服务规则           | 沿 PRD 的官网、定价、帮助规划                |

当前源码核对：`App.tsx` 的 `/` 转 `/projects`，`Rail.tsx` 已有账户菜单及禁用商业占位。核对日期为 2026-11-09；这仅说明可承接的现有结构，本文新页面并未实现。路径候选与真实路由分开，实施时同步[权威路由表](https://github.com/hrxmtc/c-foundry/blob/main/docs/reference/information-architecture-and-routes.md)。

账户菜单建议保留少量直达入口：作者中心、会员与续费、费用账单、我的订单、我的工单，以及设置与退出。作者中心内部包含商业活动入口；老墨和帮助在作品管理等非专注页面可达，具体位置由原型验证。既有团队和邀请占位不随本轮菜单设计自动变成上线能力。

## 2. 后台七项能力在作者端的对应

| 后台能力 | 作者端对应                       | 作者必须能看懂／完成                                                     |
| -------- | -------------------------------- | ------------------------------------------------------------------------ |
| 会员管理 | 作者中心、会员与续费             | 账号状态、会员状态、权益、到期及续费；免费／试用／付费与账号安全分别说明 |
| 会员账户 | 费用账单内的额度账户             | 购买额度、赠额、补偿、可用、任务预占、退款预留、到期及变动来源           |
| 订单     | 我的订单、订单详情、收银台与售后 | 买了什么、实付多少、付没付款、权益到没到账、退款到哪一步                 |
| 作品管理 | 现有我的作品、作品上下文入口     | 管理自己的作品；从某本书查看费用、提交故障工单和管理支持授权             |
| 费用账单 | 费用账单的消费明细与账期汇总     | 为哪些动作付费、对应哪本书、是否待核对；与购买／充值订单分开             |
| 发帖审核 | 老墨发布流程、我的帖子、审核通知 | 草稿、待审核、已公开、退回修改、撤回、隐藏；查看原因、重提与复核         |
| 用户工单 | 我的工单、创建工单、工单详情     | 私密提问、补充资料、跟踪答复、确认解决及重新反馈                         |

“会员”在后台索引中覆盖全部注册作者，不把未付费账号从管理中排除；“工具会员”指付费服务权益。“会员账户”是服务权益与额度的业务视图，不是新增可提现的钱包。订单解释购买，费用账单解释服务消费，两者互相关联但不混为一份记录。

## 3. 页面地图与首轮原型

下面均为设计候选；现有页面标明复用，新路径未启用。

| 编号   | 页面／候选路径                                         | 主要内容                                                     | 首轮范围                                     |
| ------ | ------------------------------------------------------ | ------------------------------------------------------------ | -------------------------------------------- |
| AUT-01 | 作者中心 `/account`                                    | 会员、官方额度摘要、待支付／待到账订单、待补充工单、返回创作 | 完整概览与二级导航                           |
| AUT-02 | 会员与续费 `/membership`                               | 当前工具权益、起止时间、可选方案、试用／续期及限制           | 当前权益、购买和到期状态；价格待定           |
| AUT-03 | 费用账单 `/billing`                                    | 额度账户、消费明细、账期汇总、充值／赠额来源、导出和票据入口 | 账户、消费与费用异议；与订单交叉定位         |
| AUT-04 | 我的订单 `/orders`、详情 `/orders/:orderId`            | 商品快照、付款、履约、退款、票据与关联工单                   | 列表、详情和关键异常状态                     |
| AUT-05 | 收银台 `/checkout/:orderId`                            | 商品、价格、限制、优惠、支付查询与恢复                       | 复用 PRD 购买闭环                            |
| AUT-06 | 我的工单 `/support`、详情 `/support/tickets/:ticketId` | 问题列表、对话、补充信息、处理记录与结果                     | 列表、创建、回复、确认与继续反馈             |
| AUT-07 | 老墨 `/laomo`、帖子 `/laomo/posts/:postId`             | 分类、搜索、教程、公开帖子及回复                             | 主列表与公开详情                             |
| AUT-08 | 我的帖子 `/laomo/mine`、编辑 `/laomo/editor/:postId`   | 草稿、提审、版本、审核结果、重提和撤回                       | 提审／退回／公开及修改中状态                 |
| AUT-09 | 我的作品 `/projects` 及现有作品页                      | 已有创作管理；作品费用与问题反馈入口                         | 只设计新增入口和授权状态，沿用创作结构       |
| AUT-10 | 设置 `/settings`                                       | 既有 LLM 配置、外观、目标、账户安全与会话                    | 增量表达两种 AI 来源，避免重复账户安全页     |
| AUT-11 | 商业活动 `/activities`                                 | 可参加活动、优惠条件、领取／使用记录                         | 后续细化；首轮保留入口和范围说明             |
| AUT-12 | 提醒入口／列表                                         | 工单答复、审核结果、回复、到账或退款需关注的变化             | 站内提醒可进入对应对象；不新增邮件或短信承诺 |

首轮用同一批演示对象串起作者与后台，覆盖会员、账户、作品定位、订单、账单、审核、工单七项能力；不只演示支付售后。具体高保真制作可分批，但整轮评审前应能核对全部七项的入口、核心页面和异常状态。

## 4. 账户与付费体验

作者中心只呈现服务概况和待处理事项，不再复制作品统计首页。会员卡和额度卡分开：前者回答“哪些工具可用、何时到期”，后者回答“官方 AI 还能消费多少、哪些额度处理中”。

### 4.1 会员与购买

- 会员页先解释权益与限制，再展示购买；自备 Key 与官方 AI 使用同一工具权益规则，官方 AI 额度单独核算。
- “续费会员”与“补充官方 AI 额度”使用不同动作名称，收银台明确商品类型和生效规则。
- 工具权益将到期但仍有官方额度时，说明使用条件及可选处理路径；赠额不得隐藏有效期。
- 到期或余额不足只在受影响的付费任务处解释；已有稿件仍可读、手工编辑、保存和导出。

### 4.2 费用账单与额度账户

费用账单建议采用三个视图：**额度账户、消费明细、账期汇总**。我的订单保持独立入口，消费详情能回到相关购买来源，订单也能查看对应额度及后续消费。

| 视图     | 作者看什么                                                 | 关键交互                                               |
| -------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 额度账户 | 可用购买额度、可用赠额／补偿、任务预占、退款预留、临近到期 | 查看每项来源和明细，补充额度；金额含币种和状态         |
| 消费明细 | 时间、作品、动作、AI 来源、正式消费／待核对／调整          | 按时间、作品、来源筛选，进入动作费用，提出异议         |
| 账期汇总 | 期初、入账、消费、退款／调整、期末与未知项                 | 按服务记录汇总和导出，标明统计截止时间；账单不冒充发票 |

账期余额按已入账变动核对；任务预占和退款预留影响可用额度，不伪装为已结算消费。BYOK 的服务商费用估算独立标识，可供查看，不加入墨鱼正式消费合计。上游平台成本不是作者账单金额。

### 4.3 AI 操作中的费用

在现有生成／分析任务处说明来源、预估和授权上限；完成后给出本次费用与详情入口。默认来源切换只影响后续动作，不在余额不足时自动更换付费来源。操作未完成、用量未知和部分完成分别说明，作者可以保留已经得到的结果。

## 5. 作品与私密求助

我的作品继续承担作者自己的作品管理。作品页新增“查看本书费用”“反馈问题”这类上下文入口，传递作品标识和相关动作，避免作者重复找订单号、任务号。

后台作品管理建议先覆盖作品标识、归属、标题、形态、管理状态、更新时间，以及必要的章节／字数统计和技术任务关联。字段是设计需要，实施前逐项核实来源；不把这些信息称为作品质量、公开上架或平台连载状态。

作者就作品提交工单时，默认只附定位问题所需的元数据。需要正文时，由作者主动选择片段，预览内容、说明用途、可查看职责和有效范围后确认；按一次明确版本的材料共享，不随以后写作自动更新为整本书访问权限。作者在工单中可查看和撤销后续访问授权；到期、撤销或工单结案后的访问和留存规则在发布前定案。

后台不提供默认代编辑、解冻、删除、转移归属或整本导出。作品的“发布”在当前创作流程中有其冻结语义，不能直接转换为运营后台的公开上架审核。

## 6. 老墨与发帖审核

用户已要求后台具有发帖审核。本稿建议首版**帖子先审后公开**；回复暂沿既有举报治理建议，是否也先审由 PRD D07 一并裁决，不默认将两者视为同一政策。受邀发帖／回复权限与审核是两个维度：有权限才可提交，审核通过才公开。

| 作者所处状态     | 看见什么                         | 能做什么                                                       |
| ---------------- | -------------------------------- | -------------------------------------------------------------- |
| 草稿             | 仅本人可见的草稿及保存状态       | 编辑、预览、提交；未受邀账号不能提交新帖                       |
| 待审核           | 提交时间和送审版本；未向社区公开 | 查看、撤回或返回自己的其他内容                                 |
| 需修改           | 对应版本、审核理由与需修改点     | 修改后重新提审，或撤回                                         |
| 已公开           | 当前公开版本、回复与公开时间     | 查看、编辑为新候选版本、撤回                                   |
| 公开帖修改待审   | 当前公开版本与新候选版本分别标注 | 查看两者、撤回候选；旧公开版保持可见，除非单独被隐藏或作者撤回 |
| 被隐藏／互动受限 | 处置范围、原因、期限及复核入口   | 查看本人理由、申请复核；私人创作照常                           |

审核针对明确版本。作者修改、撤回或管理员已处理后，旧审核页面不得再次把过期版本发布；审核失败不能覆盖仍有效的公开版。搜索、引用和提醒只展示允许公开的内容，不能泄露送审稿和隐藏正文。

“公开求助”和“私密工单”分开选择，不自动互相发布。工单答复如要沉淀为教程，需重新处理材料授权和公开内容，不能直接复制私密对话。

## 7. 用户工单

工单提供“会员与权益、订单支付、费用异议、作品／AI 故障、社区复核、其他建议”等问题类型。作者可从“我的工单”创建，也可从订单、动作、作品或审核结果直接发起；上下文由作者预览后提交，隐私材料和 Key 不默认上传。

建议状态为：**待受理 → 处理中 ↔ 待作者补充 → 已答复待确认 → 已解决 → 已关闭**。作者认为未解决可补充并返回处理中；关闭后的重开规则由 D10 确定。不虚构响应倒计时或未经确认的服务时效。

工单详情是双方有记录的回复流，显示作者可见状态、关联对象、附件／授权材料的范围及处理结论。后台内部备注、分派与技术成本信息单独保管。支付或退款结果由交易服务更新，客服在工单回复“已处理”不能修改资金事实。

首版以文本、业务对象关联和受控片段授权为基础，任意附件上传另评估范围。提交超时先查是否已创建；回复失败保留输入。工单列表区分待答复、待自己补充和已结束，可按类型与对象筛选；站内提醒直接进入对应工单。

## 8. 设计取舍与评审要点

首轮原型应让作者完成五项任务：购买并确认到账、看懂某次 AI 费用、申请退款、发帖并处理审核结果、从具体作品或交易提交并跟踪工单。后台有对应处理页面，两端使用同一批业务对象。

本轮重点评审：会员和额度是否容易混淆；订单与消费是否能互相定位；新入口是否打扰写作；审核是否清楚说明版本与理由；工单是否能在不公开稿件的情况下解决问题。

界面遵守根 [DESIGN.md](../../DESIGN.md) 的品牌、四主题、字体和状态规范，延续桌面优先。本文是设计建议，不新增正式价格、审核时效或服务承诺；D01–D10 的裁决统一在 PRD 记录。
